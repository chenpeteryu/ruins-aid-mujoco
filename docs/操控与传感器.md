# Go2 操控、反馈与同步相机记录

## 运行

在 Ubuntu 项目根目录执行：

```bash
# 键盘操控：点击 MuJoCo 窗口后按键，默认运行 60 仿真秒
.venv/bin/python 代码/control_feedback.py --mode keyboard

# 无需按键的连续验证：站立→前进→停止→后退→停止→左转→停止→右转→停止
MUJOCO_GL=egl .venv/bin/python 代码/control_feedback.py --mode demo

# 单项动作，默认 10 仿真秒，其中前 1 秒为站立落稳
MUJOCO_GL=egl .venv/bin/python 代码/control_feedback.py --mode forward
MUJOCO_GL=egl .venv/bin/python 代码/control_feedback.py --mode backward
MUJOCO_GL=egl .venv/bin/python 代码/control_feedback.py --mode left
MUJOCO_GL=egl .venv/bin/python 代码/control_feedback.py --mode right

# 关节操控/反馈验证：第 1–2 秒给 FR_thigh 增加 0.06 rad 目标偏移
MUJOCO_GL=egl .venv/bin/python 代码/control_feedback.py --mode probe
```

按键：**↑ 前进、↓ 后退、← 左转、→ 右转、空格停止并恢复站姿、Q 结束记录**。指令保持到下一个按键，不是松键即停止；指令切换约 0.5 秒平滑过渡。关闭窗口同样结束当前会话。`--seconds` 可调整运行时长，`--viewer` 可给自动动作打开查看窗口。`--no-camera` 可仅验证物理和反馈。

键盘模式按墙钟节奏运行；离屏自动验证尽可能快速运行，仍按仿真时间采样。本次交互窗口启动与关闭已验证，完整自动动作序列已验证；人工按键体验还需操作者自行试用。当前已改用专用 GLFW 操控窗口，不执行原 MuJoCo Simulate 的键盘快捷操作。鼠标左键拖动旋转视角，滚轮缩放。

## 控制接口

`robot_control.py` 提供 `make_environment()`、`Go2Control` 和 `feedback()`。控制器不需要网络或 ROS；本次“回传”指从 MuJoCo 读取反馈，供同一程序、终端和记录文件使用，没有另建远程通信服务。

1. 读取反馈：`data.qpos`、`data.qvel` 和 `data.sensordata`。
2. 50 Hz 接收归一化前后/转向指令 `control.update(data, forward, turn)`，每项范围 [-1,1]。
3. 每 0.002s 物理步计算 PD 力矩 `control.apply(data)`，写入 `data.ctrl` 后调用 `mujoco.mj_step`。
4. 每个控制周期完成 10 个物理步；调用 `mujoco.mj_forward` 更新当前姿态的传感器和相机，再保存反馈。

电机顺序：FR、FL、RR、RL；每条腿依次 hip、thigh、calf。关节数组顺序不同，程序使用模型提供的执行器—关节映射，不能直接按数组下标混用。

这是原创手写的平地对角步态，脚端轨迹经二维逆运动学转换为关节角，再用 PD 力矩控制。没有给根节点施力、直接设置机器人位移或修改姿态来伪造运动。创建环境和重置以外，机器人运动由电机力矩、重力与接触物理产生。

**本地 kp=80、kd=2**，步态周期 0.6 秒，支撑占比 0.65，抬脚高度 0.09m。比赛指南中的正式执行器 kp=40、动作缩放 0.35 及 189 维观测接口尚未接入；本程序不是正式提交模型。归一化方向指令也不是已经标定的米/秒或弧度/秒速度控制。

## 可读反馈

每次反馈有 12 个关节位置、12 个关节速度、12 个电机力矩传感值，以及：

- `imu_quat`：姿态四元数 wxyz，4 维；
- `imu_gyro`：IMU 局部坐标角速度，rad/s，3 维；
- `imu_acc`：IMU 局部坐标加速度计读数，m/s²，3 维；包含传感器物理定义的重力/支撑效应，不能直接当作世界坐标速度导数；
- `frame_pos`：IMU 安装点的世界位置，m，3 维；
- `frame_vel`：IMU 安装点的世界线速度，m/s，3 维。

模型自带 41 个传感器，共 52 个标量。原始传感器名称、类型与维数保存在 manifest.json 中。另存目标关节角、控制力矩、执行器输出，以及 `debug_ground_truth` 中的根位置、姿态角和接触数。

`frame_pos`、`frame_vel` 和 `debug_ground_truth` 用于本地诊断，不代表正式策略有权读取这些信息。控制步态只依赖关节位置/速度反馈和用户指令；跌倒保护用调试状态判定。本次没有添加 LiDAR 或接入正式传感器噪声、延迟与丢帧合同。

## 相机与时间戳

本地前视相机 `front_rgb` 固定在 `base_link` 的 (0.34,0,0.05)m，朝前下倾约 10°，垂直视场 60°，320×240 RGB uint8，10 Hz。相机随机器人姿态移动，平地上的彩色标志仅用于观察画面变化，没有碰撞。

相机位置、局部平地和标志物是本地实验配置；原始资源 XML 未修改。该相机尚未验证为赛事冻结的 RGB 传感器，不能把它直接当成正式任务合同。

每次会话独立保存到 `输出/操控反馈/<UTC时间>-<模式>-<随机标识>/`：

```text
manifest.json       环境、控制器、相机、传感器顺序和时钟定义
feedback.jsonl      50 Hz，逐行保存机器人反馈和对应指令
frames.csv          10 Hz，图像路径、仿真时间戳、反馈索引和 SHA-256
camera/*.png        320×240 原始 RGB 图像
summary.json        动作位移、转角、稳定性和记录数量
```

**对齐键为 `sim_time_ns`**，用整数物理步计算：`physics_step × 2,000,000`。反馈间隔 20,000,000ns，相机间隔 100,000,000ns。图像文件名也包含该时间戳。

每个图像对应同一条 feedback.jsonl 记录的 `camera_frame`，其时间戳与反馈完全相同，`frames.csv` 同时记录反馈索引和哈希。采样从 t=0 开始，所以 10 秒会话包含 501 条反馈、101 帧图像。磁盘写入和渲染时间只影响程序实际运行速度，不改变仿真时间戳。

每一帧渲染和反馈均在该时刻 `mj_forward` 后、下一次物理步前完成；没有把上一物理步的传感器数据错误标为当前时刻。`wall_elapsed_ns` 仅用于性能参考；UTC 开始时间保存在 manifest，不能用渲染结束的墙钟时间代替仿真采样时间。

校验自己的完整记录：

```bash
.venv/bin/python 代码/validate_feedback.py 输出/操控反馈/<会话目录>
```

校验器会检查指令产生的真实响应，而不只检查文件是否存在。缩短自动动作测试时，动作可能未达到校验阈值；连续 demo 校验以默认 24 秒为准。

机器可读结果见 `输出/仿真/control-validation.json`，跨设备相机/反馈摘样见 `docs/samples/`。完整原始会话保留本机，不批量上传 GitHub。

## 在资源包完整赛场中操控

资源包包含完整公开训练赛场 `scene/mujoco/competition-course.mjb`。其中坡道、墙体、乱石和隧道有物理碰撞；对应 GLB 仅供视觉预览。公开训练赛场不等同于正式隐藏评测场景。

从任意终端复制运行：

```bash
cd /home/cxy/桌面/人工智能比赛
.venv/bin/python 代码/control_feedback.py --scene course --mode keyboard
```

↑/↓/←/→、空格和 Q 的操作与平地相同，默认 60 秒。可加 `--seconds 300` 延长测试；碰撞造成跌倒时会自动停止，并保留此前记录。

自动短距离测试：

```bash
MUJOCO_GL=egl .venv/bin/python 代码/control_feedback.py --scene course --mode forward --seconds 6
```

2026-11-16 已在完整 MJB 中验证上述前进测试：前进 0.337m、无跌倒、61 帧图像与 301 条反馈严格对齐；桌面操控窗口启动/退出通过。完整摘要在 `输出/仿真/course-control-validation.json`。

- 本地测试出生点为 (1,1,0.30)m，不代表正式任务起点；资源包默认 keyframe 在墙角，会穿墙。
- MJB 中没有预设相机，因此程序按机器人当前姿态设置随体虚拟前视相机，保持相同安装位置、视场和采样频率；没有改写 MJB。
- 查看窗口及记录相机启用地形的几何组 3，显示的是物理场景；不等同正式 RGB 画面合同。
- 当前仅验证赛场平整区短距离前进，尚未验证此步态通过坡道、乱石、隧道或完整路线。
- 自动平地 demo 的后退距离较长，直接在赛场运行可能撞墙；请先用键盘或短距离指令检查空间。


## 方向键与提速更新

当前使用专用操控窗口，↑/↓ 前后、←/→ 转向，空格停止，Q 退出。WASD 不再用于控制，也不会在该窗口中触发线框/显示切换；不再使用 Simulate 内建快捷键处理。窗口左上角显示当前指令、时间和速度倍率。

默认速度参数由旧版的 1 提高到 2，可通过 `--speed` 调整（0.5–2.5）：

```bash
# 默认提速
.venv/bin/python 代码/control_feedback.py --scene course --mode keyboard --seconds 300
# 需要精细控制时，恢复旧版速度参数
.venv/bin/python 代码/control_feedback.py --scene course --mode keyboard --speed 1
```

这调节的是步幅参数，实际速度与参数非线性对应，不是仿真时间加速。新版平地 10 秒实测：前进 2.319m（旧版 0.687m）、后退 3.415m（旧版 1.911m）、左转 2.529rad、右转 -2.490rad。24 秒连续动作验证通过，最低机身高度 0.220m。原表及样例是旧速度参数的历史结果；新结果见 `输出/仿真/fast-control-validation.json`。
